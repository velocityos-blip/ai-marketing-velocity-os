# Website audits and Google Search Console

Enable the Google Search Console API in the operator's Google Cloud project. Create a Web application OAuth client with the exact authorized redirect URI https://viralmarketstrategy.com/vos/dashboard (use the public dashboard URL for other installations). Configure the consent screen for the read-only webmasters scope and add permitted test users or publish the app as appropriate. Store GSC_CLIENT_ID and GSC_CLIENT_SECRET in the root-owned /etc/vos/social.env file with mode 600. From the deployment directory run docker compose up -d --no-deps api.

A workspace administrator saves a public HTTPS website under Website and search performance. Public audits start immediately and repeat weekly. Connect Google Search Console with an account that can read a matching property. VOS selects the most specific matching URL-prefix property, falling back to a matching domain property. It stores the refresh credential encrypted and uses it to read the most recent available 28-day reporting window ending three days ago. Query and page rows are scoped to the saved website prefix and shared with the workspace's configured campaign agents.

The crawler samples up to six same-host pages without rendering client-side JavaScript. The dashboard shows observed HTML findings and reporting coverage. Scheduled campaigns use the latest audit and refresh it if due. Missing Google access leaves the crawl active. Changing the site clears its connection and report. Stopping audits removes the site and stored credential. Previous campaign briefs retain their evidence.
